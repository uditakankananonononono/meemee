# October 7 implementation build-out

Baseline source: f665f35. This follow-up does not overwrite the historical 187-item
source audit. Seven implementation areas have been built out so far, not seven entire
products or a general real-world readiness certification.

## SQLite migrations (historical item 28)

Three initial regression canaries failed against the original source: failed DDL
left a table, failed DML left changed data, and an embedded COMMIT published state
before a later failure. An expanded original-source run had seven failures,
including accepted transaction controls, disabled journal safety, and ledger edits.

The migrator now holds BEGIN IMMEDIATE across ledger read, SQL execution and ledger
publication. SQLite complete_statement separates statements without splitting
trigger bodies or literal semicolons. An authorizer rejects migration-controlled
transactions, savepoints, attached databases, PRAGMAs and ledger edits. Requested
migrations commit together; on failure their changes roll back. The metadata table
itself can still be initialized on a failed first run.

Targeted run: 16 passed (migration canaries plus existing operations/backup tests).
This proves local SQLite boundaries, not PostgreSQL migration safety, arbitrary
untrusted SQL containment, power-loss recovery or deployed migration rollout.
Migration authors must configure PRAGMAs outside migration scripts.

## Shell execution (historical item 10)

Two canaries failed against original source: an arbitrary workspace executable
named like an allowlisted program ran, and a 16 MiB output allocated about 33.6 MiB
before the reported cap applied. Programs are now bound to PATH-resolved executable
identities at configuration time; alternate same-basename paths are rejected.
stdout and stderr are concurrently drained with at most 200,000 retained bytes per
stream. On POSIX, timeout/cancellation kills the process group and reaps the child.
An intermediate timeout test also exposed Python 3.10's distinct asyncio.TimeoutError;
that intermediate failure was retained and corrected.

Targeted run: 23 passed (shell canaries and existing advanced/tool tests), including
both full pipes and a real child with inherited pipes. This is not command sandboxing:
an approved interpreter can run arbitrary code, tools can write outside the workspace,
operator PATH must be trusted, and descendants that create new sessions can escape a
process group. No Windows descendant-cleanup claim is made.

Original and intermediate failures, and final targeted outputs, are retained under
[evidence](evidence/). No live model/provider benchmark or production deployment was
performed. The current repository is public; local-first runtime privacy does not
mean its source repository is private.

## Audit append serialization (historical item 27)

An independent-connection barrier canary reproduced a forked audit chain:
verification failed at sequence 2. BEGIN IMMEDIATE now serializes predecessor read
and insertion across SQLite connections. Targeted audit run: 14 passed, 8 skipped
because no PostgreSQL server is configured. This does not authenticate review
actors, prevent privileged database edits, or certify distributed audit services.

## Concurrent browser-session startup

The initial full root regression exposed a real webhook dispatcher startup crash:
API/worker/dispatcher all checked for host_id before one added it. A controlled
race canary failed with duplicate column name. Serialized schema check/alter fixes
that race. A later full run exposed journal-mode initialization returning database
locked, now handled by a bounded five-second retry of only that operation.
Fifteen repeated race runs passed. Targeted browser/startup/live-server run:
13 passed, 16 skipped. This is SQLite process startup metadata, not a claim of live
browser behavior, cross-host browser sharing or production provisioning.

## Plan status transitions (historical item 23)

Three canaries reproduced running/completing dependent steps before prerequisites
and silently reopening a completed step. Status updates now require completed
prerequisites for running/done, reject illegal transitions, check expected version
before validation and return unchanged status without a new history entry. Failed
steps can reset to pending; pending to done remains allowed for supplied already-done
work. Targeted plan/API run: 13 passed, 2 warnings. This validates supplied status
updates, not proof that tasks were performed; explicit whole-plan replacement is
still an intentional revision pathway, not a scheduler or external effect check.

## Leased worker execution (historical item 93)

Two stateful-contract canaries reproduced a long run expiring with no renewal and
lease loss leading to terminal failure attempts under stale ownership. The worker
now renews at at most one-third of the lease duration, preserves the originally
claimed token for finish/fail/cancel and treats lease loss as a fencing refusal,
not a task failure. Cancellation retains lease renewal until agent settlement.
Non-leased SQLite watcher compatibility is preserved. A shared exception class
keeps PostgreSQL dependency imports out of SQLite worker startup.

Initial fixture error and intermediate cancellation compatibility hang are
retained separately, not counted as original defects. Targeted worker/account
regression: 13 passed, 2 warnings. Fresh whole root: 602 passed, 130 skipped,
2 warnings. Six areas, sixteen original failing canary cases, no feature downgrade.
Worker lease tests are stateful contracts, not a live PostgreSQL server test;
only PostgreSQL clients, not initdb/server, are available here. Real SQLite API,
worker and webhook receiver tests passed. Lease fencing cannot undo tool effects
already started, detached external operations or justify exactly-once effects.

## Docker package completeness (historical item 9)

A canary copied only the Dockerfile's source inputs and built a real wheel, which
omitted webapp and product_site. Both runtime packages are now copied. Targeted
packaging/deployment run: 4 passed. This verifies the actual wheel built from those
inputs, not a built or deployed Docker image: no Docker engine is available here.

Latest root regression: 603 passed, 130 skipped, 2 warnings. Seven implementation
areas, seventeen original failing canary cases retained, zero feature downgrades.
Earlier full runs above are historical, not the latest total. No general product
completion, production deployment or live-model quality claim is made.
